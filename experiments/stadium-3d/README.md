# サンガスタジアム 座席ビュー（プロトタイプ）

作成日: 2026-09-10

チケットを買う前に「その席から何がどう見えるか」を確かめられるか、を試す検証用プロトタイプです。
本番ページはまだありません。本番からの導線も張っていません（`docs/ui-prototype-workflow.md`）。

## 目的

席を選ぶときに手元にあるのは、真上から見た館内図です。ブロックの位置は分かりますが、
ピッチまでの距離、見下ろす角度、屋根がどこまでかかるかは分かりません。
着席視点に立ってみて、その差が伝わるかを確かめます。

| 確認したいこと | 見るところ |
| --- | --- |
| ブロックを選ぶだけで「その席の見え方」が伝わるか | 「この位置から見る」を押したあとの画面 |
| 下層と上層で見え方の差が分かるか | 同じスタンドで層を切り替える（例：E9 と E30） |
| 前後・左右で差が出るか | 「前後位置」を前方と後方で比べる |
| スマホで操作が成立するか | パネルの開閉、3Dのブロックを指でタップ |
| 概算モデルだと伝わるか | パネル末尾の但し書き |
| 距離・高さの数字が判断の役に立つか | 選択後の情報欄（ピッチ中央までの距離、視点床面高、傾斜） |

## 確認方法

GitHub Pagesで次を開きます。

```text
https://koteikara.github.io/Sanga/experiments/stadium-3d/prototype.html
```

手元で開く場合はHTTP経由にします。

```bash
python3 -m http.server 8000
# http://localhost:8000/experiments/stadium-3d/prototype.html
```

three.jsをCDN（jsDelivr）から固定バージョンで読みます。**外へ出られない環境では表示できません。**
その場合は画面が無言で空になるのではなく、理由を出します。ライセンスと利用箇所は
`THIRD_PARTY_NOTICES.md` の three.js を正とします。

## モデルの根拠と仮定

出典に基づく値と、モデル上の仮定値を分けて `prototype.js` 冒頭の `DATA` に置いています。

| 種別 | 内容 |
| --- | --- |
| 出典（京都スタジアム（仮称）インフォメーションパッケージ p.15 / p.18） | フィールド126×84m、天然芝120×77m、最前列床面はフィールド面+1.2m、最前列までメイン8.5m・バック7.5m・サイド10.5m、下層傾斜21〜24°（モデルは中間の22.5°）、上層傾斜32°、一般席幅47cm、建物高さ27.6m |
| 仮定（`DATA.assumed`） | 段の奥行き（下層0.78m・上層0.84m）、段数（下層26・上層18）、上層の後退3.8m、上層床面高10.0m、座席間隔0.52m、座席からの目線高さ+1.15m |
| ブロック名（2025年館内図） | W1〜W17 / E1〜E17・E21〜E39 / S1〜S13・S21〜S34 / N1〜N13・N21〜N34 |

「下層・上層」の区分と、ブロックをスタンド長手方向に等分する割り付けは3Dモデル用の便宜です。
実際の座席層、ブロックごとの幅とは一致しません。屋根・外壁・大型映像装置は位置も寸法も概略です。

**出典の数値と館内図の内容は、この作業では原典に当たって確認していません。** 数字を判断に使う前に
元資料と照らす必要があります。画面の但し書きにも同じことを書いています。

## 元のHTMLから直したところ

見た目の方針は変えていません。そのままだと使えない・確認観点を満たさない箇所だけ直しました。

| 直したところ | 理由 |
| --- | --- |
| 太陽光の影のカメラ範囲を±180mへ広げた | 既定は10m四方しか映さず、スタジアムのほとんどが影の計算から外れていた |
| 全体表示の距離を画面の縦横比から計算し、霧の範囲も合わせた | 固定距離だと縦長のスマホでスタジアムが画面に入りきらなかった |
| 狭い画面で操作パネルを畳めるようにし、起動時と着席視点へ移った直後は畳んでおく | パネルが画面下半分を占め、肝心のピッチが隠れていた |
| 大型映像装置を「外壁」から分け、単独のチェックに変えた | いまの位置（x=±58m、高さ14m）だとメイン・バック上層の正面に入り、ピッチが見えない。位置が未確認なので消せるようにした |
| `select` の `outline: none` をやめ、`:focus-visible` の枠を付けた | キーボード操作の現在地が消えていた |
| 操作対象の高さを44px以上、最小文字を11pxへ | `AGENTS.md`「操作対象は原則44px程度」 |
| 狭い画面で但し書きを消さないようにした（消すのは案内文だけ） | 概算モデルである断りは、狭い画面でこそ必要 |
| 操作の案内を入力機器で切り替えた | 指で触る画面に「ホイール」「Esc」は無い |
| Wスタンドで「上層」を選べないようにした | Wに上層ブロックを登録していないため、選ぶと空の一覧になっていた |
| `ctx.roundRect` が無い場合の代替を入れた | 古いiOS Safariに無く、ブロック名の描画で落ちる |
| 読み込み失敗・WebGL無しのときに理由を出すようにした | モジュールが読めないと画面が無言で空になる |
| `prefers-reduced-motion` で慣性を切るようにした | `docs/ui-prototype-workflow.md` の確認観点 |

## 確認済み（2026-09-10、Chromium／ソフトウェアGL）

CDNへ出られない環境のため、three.js 0.170.0 はnpmの同一パッケージを同じパスへ差し替えて確認しました。
importmapが指す `build/three.module.js` と `examples/jsm/controls/OrbitControls.js` は、
そのパッケージに同じパスで存在します。

- PC（1280×800）・スマホ（390×844）とも表示でき、JavaScriptのエラー・警告なし
- 横スクロールが出ない（390 / 390）
- 操作対象の高さ: select 44px、スライダー44px、主ボタン48px、副ボタン48px、チェック44px、開閉44px
- `#stand` にフォーカスすると2pxの枠が出る
- スタンドをWにすると「上層スタンド」が選べなくなり、下層へ戻る
- 着席視点の情報欄が出る（例：E30上層＝ピッチ中央まで約82.2m・視点床面高約15.6m・傾斜32°、W9下層前方＝約53.5m・約3.6m・22.5°）
- Escで全体表示へ戻り、選択したブロックは保持される
- スマホは起動時にパネルが畳まれ、案内が「ピンチ」「タップ」表記になる
- スマホで3Dのブロックを指でタップすると選択できる（S23で確認）
- 「この位置から見る」でパネルが自動的に畳まれ、ピッチが見える
- 動きを減らす設定でも起動する

## 未確認・判断が要ること

1. **大型映像装置の位置。** いまはx=±58m・高さ14mにあり、メイン・バック下層の座席の上へ浮いています。
   上層から見ると正面をふさぎます。実際の設置場所を確認して置き直すか、モデルから外すかを決める必要があります。
2. **出典の数値と館内図。** 原典に当たっていません。特にブロック名と、どのブロックが上層かの対応。
3. **仮定値（段数・段の奥行き・上層床面高）。** ここが実際とずれると、距離と高さの数字がそのままずれます。
   数字を出している以上、裏取りが要ります。
4. **ブロック内の位置の粒度。** いまは「前後」「左右」を割合で扱っていて、列番号・席番号は持っていません。
   券面から探せる形にするなら、列・席の対応表が要ります。
5. **iPhone Safari。** 未確認です。特に指2本の拡大と、着席視点での見回し。
6. **重い端末での動き。** 段床・ブロック・座席で3,000個以上を描いています。古い端末での確認が要ります。
7. **着席視点でのブロック名。** 常に手前へ描くため、ピッチの上に大きく重なります。着席視点では自動で隠す案もあります。
8. **屋根の裏側が真っ黒に見えること。** 板1枚で作っているためです。
