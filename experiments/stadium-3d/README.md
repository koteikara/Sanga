# サンガスタジアム 座席ビュー（プロトタイプ）

作成日: 2026-09-10 ／ 作り直し: 2026-10-07（公式の座席図から全席の位置を起こした版） ／
更新: 2026-10-09（印刷された番号の読み取り、見やすさ、日差し、見た目の作り込み）

チケットを買う前に「その席から何がどう見えるか」を確かめられるか、を試す検証用プロトタイプです。
本番ページはまだありません。本番からの導線も張っていません（`docs/ui-prototype-workflow.md`）。

## 現在の状態

- **全21,215席**を、公式の座席図（ベクターPDF）から1席ずつ拾って配置しています。
  ブロック・列・席番号を選ぶと、その席に座ったときの目の高さから見られます。
- 列番号・席番号は、座席図に**印刷された番号を読み取って**振っています（読めないブロックだけ数えた番号）。
- 席ごとに**見やすさ（C値）**を計算し、色分けと情報欄に出します。着席視点では前の列に観客を座らせ、
  頭でどこが隠れるかを見られます。
- 日程データの**試合の日時**を選ぶと、その時刻の太陽で光と影を合わせ、その席がキックオフ・前半終了・
  試合終了ごろに日なたか日陰かを出します。日没後は照明の光にします。
- 見た目は、段床の陰影と通路の階段、芝の縞と擦れ、ピッチ周りの看板、空と周りの山並み、観客の形まで
  作り込んでいます（ブラウザ内でデータから組み立てる方式。スマホでも動く重さに抑えています）。
- スタンドの形（八角形のボウル、上層の張り出し、角のブロック）、ピッチまでの距離、
  段の傾斜は、座席図と京都府の公開資料に合わせています。
- 床の高さ・屋根の高さ・大型映像装置の位置は、資料に数値が無いので推定です（下の「仮定」）。
- 2026-09-10の最初の版は、資料の数値を手で置いた箱のモデルでした。何がずれていたかは
  「前の版から直したこと」にあります。

## 目的

席を選ぶときに手元にあるのは、真上から見た館内図です。ブロックの位置は分かりますが、
ピッチまでの距離、見下ろす角度、屋根や上層がどこまでかかるかは分かりません。
着席視点に立ってみて、その差が伝わるかを確かめます。

| 確認したいこと | 見るところ |
| --- | --- |
| 券面の「ブロック・列・番号」から、その席の見え方が分かるか | ブロック・列・席番号を選んで「この席から見る」 |
| 下層と上層、前列と後列で見え方の差が分かるか | 例：E9 の1列と20列、E30 の1列と12列 |
| 下層後方で上層の床がどれだけかぶるか | 例：N・S 下層の後列から見上げる |
| スマホで操作が成立するか | パネルの開閉、座席を指でタップ |
| 距離・高さの数字が判断の役に立つか | 情報欄（ピッチ中央・最寄りラインまでの距離、床と目の高さ、見下ろす角度） |
| 前の人の頭がどれだけじゃまになるか | 「見やすさで色分け」、情報欄の C値、着席視点の前の観客 |
| デーゲームで日差しを避けられるか | 「試合の日時（日差し）」で試合を選び、情報欄の日なた・日陰 |
| 推定の部分が推定だと伝わるか | パネル末尾の但し書き、情報欄の注記 |

## 確認方法

GitHub Pagesで次を開きます。

```text
https://koteikara.github.io/Sanga/experiments/stadium-3d/prototype.html
```

URLの末尾に `#ブロック-列-席番号` を付けると、その席に座った状態で開きます（例：`#E30-12-20`）。
`#E30` のようにブロックだけなら、そのブロックを選んだ全体表示で開きます。

手元で開く場合はHTTP経由にします。座席データ `layout.json` を `fetch` で読むため、
ファイルを直接開くと読み込めません（画面に理由を出します）。

```bash
python3 -m http.server 8000
# http://localhost:8000/experiments/stadium-3d/prototype.html
```

three.jsをCDN（jsDelivr）から固定バージョンで読みます。**外へ出られない環境では表示できません。**
その場合も画面が無言で空になるのではなく、理由を出します。ライセンスと利用箇所は
`THIRD_PARTY_NOTICES.md` の three.js を正とします。

### 作り直す手順

PyMuPDF（PDFの図形を読むライブラリ）が要ります。このリポジトリの依存ではないので、使うときだけ
仮想環境に入れます。ライセンスは `THIRD_PARTY_NOTICES.md` を参照してください。

```bash
python3 -m venv /tmp/stadium-venv
/tmp/stadium-venv/bin/pip install pymupdf
# 上の8つのPDFを1つのディレクトリ（例: /tmp/seatpdf）に保存してから
/tmp/stadium-venv/bin/python experiments/stadium-3d/extract/build_layout.py /tmp/seatpdf experiments/stadium-3d/layout.json
```

実行すると、スタンド別の席数（資料の概数との差）、位置合わせの残差、除いた席を表示します。
座席図が更新されたときは、この表示を下の「検証」と比べてから差し替えます。

### 計算のしかた

1. **座席を拾う。** 座席図はCADから出たベクターで、1席が小さな四角形です。四角形を拾い、向きごとに分けます
   （角のブロックは45°回った図で描かれています）。
2. **縮尺を決める。** 隣り合う席の間隔を、資料の一般席幅47cmとみなしてページの縮尺を決めます。
3. **列とブロックに分ける。** 前後の位置で列にまとめ、通路の切れ目でブロックに分け、図中のブロック名
   （W9 など）と対応づけます。名前が読めないブロックは並びから補います（情報欄に注記）。
4. **スタジアムの座標へ置く。** 全体図からスタンドの前面の線（下層はピッチまでの距離、上層は3・4F図の
   上層前面）と、ブロックの境目を読み取り、各ページを回転・平行移動で当てはめます（最小二乗）。
5. **列番号と席番号を振る。** 座席図に印刷された番号を読みます（`extract/glyphs.py`）。
   - 席番号は、座席の四角の中に CAD の線の文字で描かれています。線をつながりでまとめて1文字ずつ取り出し、
     7×11 のます目に描き直して、0〜9 の型（W7〜W11 のページで全席に番号がある列から作った形）と比べます。
     6・8・9 は穴の数と位置も見ます。
   - 列番号は、通路に置かれた小さな白黒画像です。斜めのブロックの番号は数字ごと45°傾いた画像なので、
     回して読みます。番号ごとに、どの列の延長線にいちばんぴったり乗るかで持ち主を決め、
     前から後ろへ番号が増える並びだけを使います。
   - 印刷された番号がある席はその番号、ない席は同じ列の印刷された番号から席の間隔で数えます。
     列番号が読めないブロックは、隣の列番号との段のずれから、それもなければ前から数えます。
     ブロックごとの出どころは `layout.json` の `rowNumbers` / `seatNumbers`（`print` か `count`）に残し、
     `count` のときは情報欄に注記します。
6. **高さを付ける。** 下層は最前列床1.2mから、傾斜21°→24°で積み上げます。上層は1列目の床を
   下層最後列の床の2.5m上とし、32°で積み上げます。

## 見やすさ（C値）

観客席の設計で使われる「前の人の頭越しに見えるか」の目安です。自分の目からピッチの手前の端
（いちばん近いタッチライン・ゴールライン上の点）への視線が、前の列の人の目の高さよりどれだけ
上を通るかを計算します（`sightlines.js`）。最前列は、前の人の代わりに前の壁の上端を越えるものとします。

| 区分 | C値 | 席数（2026-10-09） |
| --- | --- | ---: |
| とても見やすい | 120mm以上 | 1,845 |
| 見やすい | 90〜120mm | 2,828 |
| 前の人の頭の間から見る | 60〜90mm | 5,723 |
| 前の人で隠れやすい | 60mm未満 | 10,819 |

頭は目より10cmほど上にあるので、90mm以上あれば頭越しに見えます。

**この数字は床の高さの推定にそのまま左右されます。** 上層の多くの席が60mm未満になっているのは、
上層の床（1列目10.3m）がピッチに対して高すぎる推定になっている可能性があります（傾斜32°の段で、
手前のタッチラインへの視線の角度とほぼ同じになる）。「未確認」の1を確かめるまでは目安として扱います。

## 日差し

`sun.js` で、日付と時刻から太陽の方位と高度を近似式（NOAA の簡易式、誤差1°程度）で計算します。
京都の夏至の正午で高度78.4°、冬至の正午で31.5°になることを確かめています。

- スタジアムの位置と向きは OpenStreetMap のピッチの形から測りました。ピッチの長辺は真北から約3.8°西へ傾いています。
- 席が日なたか日陰かは、その席の目の高さから太陽へ向けた線が、屋根・建物・スタンド・大型映像装置に
  当たるかで決めます。南側のガラス屋根は光を通すものとして扱います。
- 太陽が沈んだあとは、照明の光（屋根の西の縁から斜めに当たる白い光）に切り替えます。
  照明の位置・向きは実物を確かめていません。
- 例：2026-10-31 14:00（太陽は南西・高度31°）は、E30 12列20番はキックオフ・前半終了は屋根の陰、
  試合終了ごろは日が傾いて日なた。W9 10列12番は3つとも日陰。

## 見た目の作り込み（2026-10-09）

いまの方式（ブラウザ内でデータから組み立てる）のまま、次を足しました。画像ファイルは使わず、
模様はその場で描いています。

| 部分 | 内容 | 実物との関係 |
| --- | --- | --- |
| 段床 | 踏み面は明るく、蹴上げと上層の軒裏は暗く。コンクリートのざらつき | 色は推定 |
| 通路の階段 | 1列を2段で上る階段。段の縁は黄色 | 段の割り方・色は推定 |
| 芝 | 5mごとの刈り込みの縞、細かなムラ、ゴール前とセンターの擦れ | 雰囲気 |
| 看板 | タッチラインの外4m・ゴールラインの外4.5mに高さ0.9mの LED 看板。図柄はクラブ名と模様だけ | 位置・内容は未確認 |
| コーナーフラッグ・ゴールネット | フラッグは高さ1.5m、ネットは12cmの網目 | 一般的な寸法 |
| 外壁 | 縦のルーバーと階ごとの帯 | 模様は推定 |
| 空・周りの山並み | 空のグラデーションと、盆地を囲む低い山並みの遠景 | 山の形は実際のものではない |
| 観客 | 肩・首・肌・髪のある座った人。服は紫を多めに | 雰囲気 |

重さ（2026-10-09、`?debug` で `renderer.info` を確認）：全体表示で約67万三角形・描画265回、
着席視点で約113万三角形（観客込み）。観客は半径35m以内だけに置き、影は落としません。
座席は脚を省いた2部品です。

地面は、周囲の平地・スタジアムの床・人工芝帯・天然芝を重ならない形に分けています。
重ねた板は、奥行きの精度が低い端末（ソフトウェア描画など）で前後が入れ替わり、芝と白線が消えていました。

## 焼き付け版（B、2026-10-09 試作・途中）

**状態（2026-10-09）：作る仕組みまで。焼き付けたモデル本体（`baked/stadium-baked.glb`）はまだ入っていません。**
試し焼き（低い品質）で、上層の床の裏などに陰影が付くことは画面で確かめました。本番の品質での焼き付け、
圧縮、通常版との見比べは次の作業です。GLB が無いあいだは `?baked` を付けても通常のモデルのまま表示します。

URL に `?baked` を付けると、構造物（段床・前面の壁・屋根・建物・地面とピッチ）を、Blender で陰影
（アンビエントオクルージョン：物の陰になる所ほど暗くなる陰影）を焼き付けた部品に差し替えます。
座席・観客・看板・トラスなどはそのままです。上層の床の裏、下層の後方、段の隅、屋根の裏が、
物の陰で暗くなります。太陽の光と影はこれまでどおり時刻に合わせて動きます（焼き付けたのは空からの光の陰影だけ）。

```text
https://koteikara.github.io/Sanga/experiments/stadium-3d/prototype.html?baked#E9-20-15
```

### 作り方

| 段階 | ファイル | 内容 |
| --- | --- | --- |
| 1 | `bake/export-scene.mjs` | ブラウザ版のモデルを組み立て、構造物を GLB に書き出す（Playwright） |
| 2 | `bake/build_stands.py` | 段床を `layout.json` から「見える面だけ」で作り直す。ブラウザ版の段床は箱の重なりで隠れた面が多く、焼くと画像の大半が無駄になるため |
| 3 | `bake/bake_ao.py` | Blender で、部品ごとに陰影用の UV（2つ目の UV）を詰め、Cycles で陰影を焼き、glTF の遮蔽テクスチャとして付けて書き出す |
| 4 | glTF Transform | 形を meshopt で圧縮する。画面では three.js 同梱のデコーダーで解く |

```bash
# リポジトリの根元で
python3 -m http.server 8123 --bind 127.0.0.1 &
node experiments/stadium-3d/bake/export-scene.mjs /tmp/scene.glb
python bake_ao.py /tmp/scene.glb experiments/stadium-3d/layout.json /tmp/baked.glb   # Blender 4.2 の Python（pip の bpy でも可）
npx @gltf-transform/cli meshopt /tmp/baked.glb experiments/stadium-3d/baked/stadium-baked.glb
```

Blender・glTF Transform・Playwright はこのリポジトリの依存ではありません（`THIRD_PARTY_NOTICES.md`）。
`layout.json` やブラウザ版の構造物の形を変えたときは、焼き直しが要ります（焼き付け版は形を写し取ったもの）。

   ここがずれると、見下ろす角度と上層のかぶり方がそのままずれます。断面図か実測で確かめたいところです。
