# サンガスタジアム 座席ビュー（プロトタイプ）

作成日: 2026-09-10 ／ 作り直し: 2026-10-07（公式の座席図から全席の位置を起こした版）

チケットを買う前に「その席から何がどう見えるか」を確かめられるか、を試す検証用プロトタイプです。
本番ページはまだありません。本番からの導線も張っていません（`docs/ui-prototype-workflow.md`）。

## 現在の状態

- **全21,215席**を、公式の座席図（ベクターPDF）から1席ずつ拾って配置しています。
  ブロック・列・席番号を選ぶと、その席に座ったときの目の高さから見られます。
- スタンドの形（八角形のボウル、上層の張り出し、角のブロック）、ピッチまでの距離、
  段の傾斜は、座席図と京都府の公開資料に合わせています。
- 床の高さ・屋根の高さ・大型映像装置の位置は、資料に数値が無いので推定です（下の「仮定」）。
- 2026-09-10の最初の版は、資料の数値を手で置いた箱のモデルでした。何がずれていたかは
  「前の版から直したこと」にあります。

## 目的

席を選ぶときに手元にあるのは、真上から見た館内図です。ブロックの位置は分かりますが、
ピッチまでの距離、見下ろす角度、屋根や上層がどこまでかかるかは分かりません。
着席視点に立ってみて、その差が伝わるかを確かめます。

| 確認したいこと | 見るところ |
| --- | --- |
| 券面の「ブロック・列・番号」から、その席の見え方が分かるか | ブロック・列・席番号を選んで「この席から見る」 |
| 下層と上層、前列と後列で見え方の差が分かるか | 例：E9 の1列と20列、E30 の1列と12列 |
| 下層後方で上層の床がどれだけかぶるか | 例：N・S 下層の後列から見上げる |
| スマホで操作が成立するか | パネルの開閉、座席を指でタップ |
| 距離・高さの数字が判断の役に立つか | 情報欄（ピッチ中央・最寄りラインまでの距離、床と目の高さ、見下ろす角度） |
| 推定の部分が推定だと伝わるか | パネル末尾の但し書き、情報欄の注記 |

## 確認方法

GitHub Pagesで次を開きます。

```text
https://koteikara.github.io/Sanga/experiments/stadium-3d/prototype.html
```

URLの末尾に `#ブロック-列-席番号` を付けると、その席に座った状態で開きます（例：`#E30-12-20`）。
`#E30` のようにブロックだけなら、そのブロックを選んだ全体表示で開きます。

手元で開く場合はHTTP経由にします。座席データ `layout.json` を `fetch` で読むため、
ファイルを直接開くと読み込めません（画面に理由を出します）。

```bash
python3 -m http.server 8000
# http://localhost:8000/experiments/stadium-3d/prototype.html
```

three.jsをCDN（jsDelivr）から固定バージョンで読みます。**外へ出られない環境では表示できません。**
その場合も画面が無言で空になるのではなく、理由を出します。ライセンスと利用箇所は
`THIRD_PARTY_NOTICES.md` の three.js を正とします。

### 操作

| 画面 | PC | スマホ |
| --- | --- | --- |
| 全体表示 | ドラッグで回転、ホイールで拡大、座席をクリックで選択（ポインタを載せると席名を表示） | ドラッグで回転、ピンチで拡大、座席をタップで選択 |
| 着席視点 | ドラッグ・矢印キーで見回す、ホイールで画角、Escで全体表示 | ドラッグで見回す、「全体表示へ戻る」 |

着席視点のまま列や席番号を変えると、その席へ座り直します。全体表示では、選んだブロックの座席を
明るい紫、選んだ席を黄色で塗り、席の上に目印を立てます（座ると元の色に戻します）。

## 座席データの作り方

### 使った資料

| 資料 | 使ったところ | URL | 確認日 |
| --- | --- | --- | --- |
| サンガスタジアム by KYOCERA「座席案内」の座席図（全体図 `seat_map_202009.pdf`、ブロック別 `w1_w17.pdf` `e1_e17.pdf` `e21_e39.pdf` `n1_n13.pdf` `n21_n34.pdf` `s1_s13.pdf` `s21_s34.pdf`） | 全席の並び、ブロック名、スタンドの外形、上層の位置 | https://sangastadium-by-kyocera.jp/seat-guide （PDFは `https://sangastadium-by-kyocera.jp/cmscp/wp-content/themes/mymall/img/seat/` 以下） | 2026-10-07 |
| 京都府「京都スタジアム（仮称）インフォメーションパッケージ」平成30年1月 p.15、p.18 | 席幅、最前列床の高さ、ピッチまでの距離、傾斜角、屋根の張り出し、スタンド別の席数（検証用） | https://www.pref.kyoto.jp/sposei/news/documents/11ms.pdf | 2026-10-07 |

**PDFそのものはリポジトリに入れません**（スタジアム運営・京都府の公開物で、再配布しない）。
コミットするのは、そこから計算した座標（どの席がどこにあるかという事実）の `layout.json` と、
計算に使ったスクリプトだけです。取り直すときは、公式サイトへの取得間隔を10秒以上空けます
（`docs/supporter-timeline-design.md`「公式サイトの利用条件」と同じ扱い）。

### 作り直す手順

PyMuPDF（PDFの図形を読むライブラリ）が要ります。このリポジトリの依存ではないので、使うときだけ
仮想環境に入れます。ライセンスは `THIRD_PARTY_NOTICES.md` を参照してください。

```bash
python3 -m venv /tmp/stadium-venv
/tmp/stadium-venv/bin/pip install pymupdf
# 上の8つのPDFを1つのディレクトリ（例: /tmp/seatpdf）に保存してから
/tmp/stadium-venv/bin/python experiments/stadium-3d/extract/build_layout.py /tmp/seatpdf experiments/stadium-3d/layout.json
```

実行すると、スタンド別の席数（資料の概数との差）、位置合わせの残差、除いた席を表示します。
座席図が更新されたときは、この表示を下の「検証」と比べてから差し替えます。

### 計算のしかた

1. **座席を拾う。** 座席図はCADから出たベクターで、1席が小さな四角形です。四角形を拾い、向きごとに分けます
   （角のブロックは45°回った図で描かれています）。
2. **縮尺を決める。** 隣り合う席の間隔を、資料の一般席幅47cmとみなしてページの縮尺を決めます。
3. **列とブロックに分ける。** 前後の位置で列にまとめ、通路の切れ目でブロックに分け、図中のブロック名
   （W9 など）と対応づけます。名前が読めないブロックは並びから補います（情報欄に注記）。
4. **スタジアムの座標へ置く。** 全体図からスタンドの前面の線（下層はピッチまでの距離、上層は3・4F図の
   上層前面）と、ブロックの境目を読み取り、各ページを回転・平行移動で当てはめます（最小二乗）。
5. **列番号と席番号を振る。** 最前列を1列とし、席番号は各列の観客から見て左端を1とします。
   席の欠けた位置（通路・車いす席など）は番号を飛ばします。
6. **高さを付ける。** 下層は最前列床1.2mから、傾斜21°→24°で積み上げます。上層は1列目の床を
   下層最後列の床の2.5m上とし、32°で積み上げます。

## モデルの根拠と仮定

| 種別 | 内容 | 置き場所 |
| --- | --- | --- |
| 座席図から | 全席の水平位置、列、席番号、ブロック名、スタンドと上層の外形、2F・3F・4Fの建物の外形 | `layout.json` |
| 資料から（p.15、p.18） | 席幅47cm、最前列床はフィールド面＋1.2m、最前列までメイン8.5m・バック7.5m・サイド10.5m、下層傾斜21〜24°、上層傾斜32°、屋根は最前列より2m張り出す、フィールド126×84m、天然芝120×77m | `extract/build_layout.py` 冒頭 |
| 仮定（高さ） | 下層の傾斜が21°から24°へ変わるまでの奥行き17m、上層1列目の床は下層最後列（奥行き16m）の床の2.5m上 | `extract/build_layout.py` 冒頭 |
| 仮定（見た目） | 屋根の内側の端の下面は上層最上列の床から5.0m上、外側は2.0m上、トラスのせい1.8m、着席時の目の高さ1.15m、大型映像装置は幅10m×高さ5.6m | `stadium-model.js` の `LOOK` |
| 推定（大型映像装置の位置） | 上層の南西（S22・S23）と北東（E38・E39）の角は3列しかなく、その後ろに座席がない。資料p.15の2基はこの2か所と推定 | `stadium-model.js` の `buildScreens` |
| 推定（屋根の材料） | 南サイドの屋根をガラス（光を通す）、ほかを金属板として描く | `stadium-model.js` の `buildRoof` |
| 補った部分 | S8 は座席図に半分しか描かれていないため、S6 を S7 の中心で左右反転して作った | `layout.json` の `mirroredFrom` |

座席の色、手すりの形、メインスタンド上階（ガラス面）の中の様子、照明の位置は実物を確かめていません。

## 前の版から直したこと（2026-10-07）

2026-09-10の版は、資料の数値と仮定値でスタンドを箱として置いたモデルでした。座席図と重ねると、
次のずれがありました。

| 前の版 | いまの版 |
| --- | --- |
| スタンドの前面がピッチから約8m遠かった（最前列までの距離を二重に足していた） | 座席図の前面の線と資料の距離に合わせた |
| 北と南が入れ替わっていた | 全体図の向き（メインが西）に合わせた |
| 4つの長方形のスタンド | 角のブロックを含む八角形のボウル |
| ブロックをスタンドの長さで等分していた | 座席図のブロックの位置と幅 |
| 列・席番号が無く、「前後・左右」を割合で選んでいた | ブロック・列・席番号で選べる |
| 座席は1.2m間隔・最大16列の簡易表現 | 47cm間隔で全21,215席 |
| 上層は一律に3.8m後退した箱 | 上層の前面の線（3・4F図）と、下層への張り出し |
| 大型映像装置が x=±58m・高さ14m で下層の上に浮いていた | 上層の角（推定）の後ろ |
| 屋根は板1枚 | 内側から外へ下る屋根面とトラス |

画面まわりで前の版から引き継いでいること：狭い画面で操作パネルを畳める（起動時と着席時は畳む）、
操作対象の高さ44px以上、`:focus-visible` の枠、入力機器に合わせた案内文、読み込み失敗・WebGL無しの
ときの理由表示、`prefers-reduced-motion` で慣性を切る、`ctx.roundRect` が無い環境の代替。

このほか、広い画面では全体表示の中心を操作パネルの右側へずらし、スタジアムがパネルの裏に隠れないようにしました。
ブロック名の札は最前列の上に置き、屋根や手前のスタンドに隠れるようにしました（前の版は常に手前に描いていた）。
着席視点では、32m以内の札を隠します。

## 確認済み（2026-10-07、Chromium／ソフトウェアGL）

CDNへ出られない環境のため、three.js 0.170.0 はnpmの同一パッケージを同じパスへ差し替えて確認しました。
importmapが指す `build/three.module.js`、`examples/jsm/controls/OrbitControls.js`、
`examples/jsm/utils/BufferGeometryUtils.js` は、そのパッケージに同じパスで存在します。

- PC（1280×800）・スマホ（390×844）とも表示でき、JavaScriptのエラー・警告なし。横スクロールなし
- 着席視点（E30 12列20番、W9 10列12番、N26 18列6番、S5 3列10番、E9 20列15番）で、ピッチ・対面スタンド・
  上層と屋根の裏が見える。情報欄の例：E30 12列20番＝ピッチ中央まで約62m・床の高さ約16.1m・目の高さ約17.3m・
  見下ろす角度約16°、W9 10列12番＝約51m・約4.3m・約5.4m・約6°
- 全体表示で座席をクリックすると、その席（例：W10 9列2番、N10 17列12番）が選ばれ、選択欄も合う。ピッチをクリックしても選ばれない
- スマホで座席をタップすると選べる（W6 13列16番）。「この席から見る」でパネルが畳まれる
- 着席したまま列を変えると、その列へ座り直す
- Escで全体表示へ戻り、選んだ席は保持される
- 操作対象の高さ：選択欄44px、ボタン48px、チェック44px以上。`#block` にフォーカスすると枠が出る
- `layout.json` が読めないときは、理由を画面に出す
- URLの `#E30-12-20` で、その席に座った状態から始まる

## 未確認・判断が要ること

1. **床の高さ。** 傾斜角は資料の値ですが、傾斜が変わる位置と上層の床の高さは推定です。
   ここがずれると、見下ろす角度と上層のかぶり方がそのままずれます。断面図か実測で確かめたいところです。
2. **列番号・席番号の振り方。** 座席図の番号の文字は読まず、「最前列が1列、観客から見て左端が1番」として
   数えています。とくに上層の角のブロックは列の数え方がずれている可能性があります（情報欄に注記）。
   券面との突き合わせが要ります。
3. **大型映像装置の位置。** 座席の欠け方からの推定です。「大型映像（推定）」で消せます。
4. **屋根の高さ・形・材料。** 断面図の比率からの推定です。南側をガラスとしたのも確認していません。
5. **iPhone Safari と重い端末。** 未確認です。座席は1つのインスタンスで描いていますが、21,215席×3部品で
   約76万三角形あります。古い端末で重い場合は、遠いスタンドの座席を間引くなどの対策が要ります。
6. **公式サイトの利用条件。** サンガスタジアム by KYOCERA のサイトには、2026-10-07時点でサイトマップに
   利用規約のページが無く、プライバシーポリシーにも著作物の扱いの記載がありませんでした。座席の位置という
   事実だけを使い、図面・画像・文章そのものは載せていませんが、本番へ出す前には運営者への確認を検討します
   （`docs/source-and-license.md`）。
7. **座席図の更新。** ブロック別PDFは2026年8月1日更新版です。座席図が変わったら作り直しが要ります。
