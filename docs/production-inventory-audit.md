## 経緯

本番サーバーにはリポジトリ外で直接置いたファイルがあり、FTP同期の管理外のまま取り残されていました。取り込みワークフローで88件を `public/` へ取り込み、正本をリポジトリに一本化した直後に、公開物全体を棚卸ししたものです。

取り込み時点の内訳は、管理済み83件 / 取り込み88件 / 除外1件（`.ftp-deploy-sync-state.json`）でした。

棚卸しの結果、未参照アセットと検証用プロトタイプをサーバーから取り除き、2026-08-26時点でサーバー上のファイルはリポジトリの `public/` と一致しています。

## 参照されていないファイル

`public/` 配下の全ファイルについて、HTML・CSS・JavaScript からの参照を機械的に追跡した結果です。テンプレートリテラルで組み立てる `assets/players/<背番号>.webp` は動的参照として参照済みに数えています。

| ファイル | 判定 |
| --- | --- |
| `public/images/`（39件） | **削除済み。** 等倍版（159×37）の旧背番号画像。画像パスを `img/` へ切り替えた際の残骸 |
| `public/default_page.png` | 780×577。レンタルサーバーの初期ページ用と見られる。参照元なし |
| `public/data/matches.sample.json` | 検証・フォールバック用のサンプル |
| `public/data/hotel-index.json` | 0件。ホテル機能は画面未実装 |
| `public/data/hotels/.gitkeep` | 空ディレクトリ保持用 |
| `public/assets/vendor/modern-screenshot/LICENSE`、`VENDOR.md` | 第三者ソフトウェアの権利表示。配信不要だが削除しない |
| `public/.htaccess` | `.mjs` のMIME type設定。サーバー設定として必要 |
| `public/.nojekyll` | GitHub Pages用 |

`public/images/` は、同名39件すべてが `public/img/` と内容の異なる等倍版で、参照元がリポジトリ内に存在しませんでした。画像パスを `images/` から `img/`（2倍解像度）へ切り替えたときに、旧ディレクトリがサーバー上に残ったものです。棚卸しで削除しました。復元が必要な場合はこのコミットの親から取得できます。

サーバーへ直接アップロードする運用では、こうした切り替えの残骸が誰にも気づかれないまま残ります。リポジトリ経由に一本化した以降は、参照されなくなったファイルが差分として見えるようになります。

## 棚卸しで決めたこと

### 1. `public/images/` を削除する

画像パスを `img/` へ切り替えた際に残った等倍版アセット39件（528KB）。参照元がなく、残す理由がないため削除します。

**サーバー上の実物はデプロイでは消えませんでした。** 後述の「FTP同期が削除できる範囲」のとおり、同期の記録に無いファイルはActionの対象外です。2026-08-26にFTPで手動削除し、走査で消えたことを確認しています。

### 2. `public/experiments/` を削除する

検証用のプロトタイプが本番サーバーで公開されていました。`docs/project-structure.md` は `experiments/` を「公開前の検証用。公開物の正本ではない」としており、方針と実態が食い違っていました。

当初はデプロイの `exclude` で除外しましたが、これは誤りでした。除外したファイルは同期の比較対象から外れるだけでサーバー上には残り、さらに**除外した回に同期の記録からも落ちる**ため、以降はActionから見えなくなります。自動削除できたはずのものを、手動削除しか手段のない状態にしてしまいました。

`public/experiments/` 自体を削除し、リポジトリ直下の `experiments/` を唯一の正本にしています。サーバー上の実物は2026-08-26にFTPで手動削除しました。

副次的に、`public/experiments/` とルート `experiments/` の二重管理も解消しました。

公開対象から外したいものは、`exclude` に足すのではなく `public/` に置かないことで対応します。

### 3. 被リンクのない旧ページは維持する

`sanga2025.html`、`sanga2025season.html`、`sanga_slides.html`、`TradePost/index-v1.html` は、直URLで共有されている可能性を考慮して残します。現行機能ではないため、仕様変更や改修の対象にはしません。

## FTP同期が削除できる範囲

本番デプロイの `SamKirkland/FTP-Deploy-Action` は、サーバー上の `.ftp-deploy-sync-state.json` に記録されたファイルだけを比較します。**このActionが過去にアップロードしたことのないファイルは、存在自体を認識せず、削除対象にもなりません。**

2026-08-26のデプロイ実行時のログがこれを示しています。

```
Local Files:  133
Server Files: 82
Uploading: 815 kB -- Deleting: 0 B -- Replacing: 0 B
```

サーバー上には172件のファイルがありましたが、同期が認識していたのは82件でした。プロジェクト外で直接置いたファイル（`img/`、`images/`、`TradePost/`、`sanga2025*` など90件）は記録に無く、削除も更新もされません。

この取り込み作業により、51件が同期管理下に入りました。以降はリポジトリ側の削除がサーバーへ反映されます。

一方、`images/` はリポジトリから削除済みでサーバーへ送られないため、同期管理下に入る機会がありませんでした。`experiments/` も `exclude` に入れた回に記録から落ちました。**どちらもデプロイでは削除できず、FTPでの手動削除が必要でした。**

`exclude` に入れたファイルも同じく比較対象から外れ、記録からも落ちます。公開対象から外したいものは、除外ではなく `public/` に置かないことで対応します。

### 削除後の実測

`images/` と `experiments/` を手動削除したあとの走査結果です。

| 分類 | 削除前 | 削除後 |
| --- | --- | --- |
| 管理済み（`public/` に同名あり） | 123件 | 123件 |
| 取り込み候補（管理外の残骸） | 48件 | **0件** |
| 除外（`.ftp-deploy-sync-state.json`） | 1件 | 1件 |
| 合計 | 172件 | 124件 |

サーバー上のファイルはリポジトリの `public/`（124ファイル）と一致し、管理外のファイルは無くなりました。

## 調査方法

参照関係は、`public/` 配下のHTML・CSS・JavaScriptから次を抽出して追跡しました。

- `src=` / `href=` 属性
- CSSの `url()`
- ES Moduleの `from "..."`
- 文字列リテラル中の資材パス（`.png`、`.css`、`.js`、`.json` など）

いずれもバージョンクエリ（`?v=...`）を取り除いてから解決します。テンプレートリテラルで組み立てるパスは機械的に追えないため、`assets/players/` のように基点ディレクトリ単位で参照済みとして扱いました。同じ調査をやり直す場合は、この前提を引き継いでください。
