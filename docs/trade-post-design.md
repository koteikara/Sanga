## 作り直す理由

現行ツールは、ほぼ使われていません。原因を実地で調べたところ、**投稿が誰にも見つからない形で出力されていた**ことが分かりました。

### 誰も見ていないタグを出力していた

Yahoo!リアルタイム検索（Xをログインなしで検索できる）で、2026-09-09に確認した結果です。

| タグ | 投稿 |
| --- | --- |
| `#サンガガチャ交換` | あり（2026-08-29、08-30 ほか） |
| `#サンガグッズ交換` | あり（2026-08-23、08-29、08-30 ほか） |
| `#京都サンガ` | 交換投稿で頻出 |
| **`#京都サンガ交換希望`**（現行ツールが出力する） | **0件（「一致する情報は見つかりませんでした」）** |
| `#Jリーグ交換` | 0件 |

京都サンガのグッズ交換はXで現に動いています。現行ツールだけが、実在しないタグを吐いていました。

### 入力を自由文にしていた

現行ツールは「譲るもの」「求めるもの」を1行の自由文で受け取り、その文字列をそのままハッシュタグにします
（`public/TradePost/script.js` の `#${offerItem.replace(/ /g, "")}`）。
`#ホーム浦和戦Sメイン` のような、検索されないタグが生成されます。

実際の投稿は後述のとおり**商品名＋背番号の集合**です。1行の自由文では表現できません。

## Xでの交換の実態

2026-09-09に、Yahoo!リアルタイム検索で `#サンガガチャ交換` `#サンガグッズ交換` および
`京都サンガ 交換 ガチャ` を確認しました。以下は実際の投稿から読み取った書き方です。

```text
🟣ガチャ交換🟣 譲）ユニ型缶バッジ 2 求）同種44
譲）ユニ型キーホルダー 2、23、38 求）同種44
次戦、日産スタジアムorホーム柏レイソル戦での交換🉑          （2026-08-30）

換、買取 (譲) ユニホーム缶バッチ 2.8.34.50 キーホルダー 17.29.31 (求) 9 、定価   （2026-08-23）

RENCAブース 参加賞ステッカー 譲: 31 平賀 求: 25 尹 48 中野      （2026-08-30）

8/29福岡戦で発売された京都サンガガチャ(ラバーユニフォーム)10番(1st.2nd)、11番(2nd)を
買取させてくださる方                                              （2026-08-29）
```

読み取れる文法は次のとおりです。

| 要素 | 実際の書き方 |
| --- | --- |
| 単位は背番号 | `譲) 2.8.34.50` `求) 9`。商品名は1回だけ書き、あとは番号を並べる |
| 区切り | `.`（ドット）が最多。`、`（読点）も使われる |
| 商品は種類で呼ぶ | ユニ型缶バッジ／ユニ型キーホルダー／ラバーユニフォーム／参加賞ステッカー |
| 表記ゆれがある | 「ユニ型缶バッジ」と「ユニホーム缶バッチ」が同じ商品を指している |
| 1st / 2nd | `10番(1st.2nd)`、`求)1st:2.7.18` |
| 「同種」 | `求）同種44` ＝ 直前に挙げた商品と同じものの44番。1投稿に複数商品を並べたときの省略 |
| 受け渡しは試合 | `次戦、日産スタジアムorホーム柏レイソル戦での交換🉑` |
| 発売も試合に紐づく | `8/29福岡戦で発売された` |
| 交換だけではない | `換、買取`／`定価`／`300円で交換` |

**この2軸——商品×背番号と、試合——を、このリポジトリは正本として持っています。**
`public/data/players.json`（背番号つき、有効39件）と `public/data/matches.json`（57件）です。

> 出典はYahoo!リアルタイム検索経由の確認です。投稿者・日付・商品名まで具体的に取れているため実在は堅いと判断していますが、
> 商品の正式名称は公式の表記と突き合わせる余地があります。「未確定事項」を参照してください。

## 設計

**「投稿をつくる」と「募集をさがす」の二枚看板にします。**
作るだけでは、投稿しても見つけてもらえるまで待つしかありません。探す側を持つことで、
既に出ている投稿へ自分から届きます。**探す側は導入初日から機能します。**タグの普及を待ちません。

### つくる

**1つの投稿に商品を複数組のせられます。**実際の投稿がそうなっているためです
（`譲）ユニ型缶バッジ 2 求）同種44 / 譲）ユニ型キーホルダー 2、23、38 求）同種44`）。
1組ごとに次を選びます。

1. 商品を選ぶ（`goods.json` から）
2. 種別を選ぶ（1st / 2nd など。商品が持つときだけ表示）
3. 譲る背番号を選ぶ（`players.json` から複数選択）
4. 求める背番号を選ぶ（複数選択）

組を足したあと、投稿全体に対して次を選びます。

5. 受け渡しの試合を選ぶ（`matches.json` の今後の試合から複数選択）、郵送の可否
6. 補足（任意の自由文）
7. 投稿文と画像を出力する

### さがす

同じ選択のまま、いま出ている募集への検索リンクを出します。

| 行き先 | 理由 |
| --- | --- |
| Yahoo!リアルタイム検索 | Xの投稿をログインなしで検索できる |
| X検索 | ログインしていれば新着順で追える |

### タグの方針

**新しいタグを発明しません。** 実在が確認できたタグだけを `goods.json` に持ち、そこから出力します。
現行の `#京都サンガ交換希望` は削除します。

## 商品名の取得元

**商品名は公式から取ります。**推測しません。取得元は2つです。

| 取得元 | 何が取れるか |
| --- | --- |
| 公式ニュースの新商品告知（[例](https://www.sanga-fc.jp/news/detail/21402)） | **毎試合出ます。**題名に対象試合が入り、商品ごとに見出しが立ちます。ガチャかどうか、ラインナップ数（「全選手対応(35選手)」）も書かれています |
| [オフィシャルオンラインショップ](https://sanga-onlineshop.com/) | ガチャ以外がこちらで展開されることがあります |

2026-09-09の告知（9/11柏戦）からは、ガチャ商品として
`VICTORY ガチャ【第一弾】`、`VICTORY ガチャ【第二弾】`、`ミニ色紙風アクリルキーホルダー` が取れました。
Xの投稿で「ビクトリーガチャ」と呼ばれていたものの正式名称が、これで確定しています。

### 何を持ち、何を持たないか

`docs/supporter-timeline-design.md` の「公式サイトの利用条件」は、
**記事本文とタイトルを保存も転載もしない**、公式由来の画像を使わない、と決めています。
本ツールもこれを引き継ぎ、次の線を引きます。

| 持つ | 持たない |
| --- | --- |
| 商品の正式名称（交換に必要な固有名詞） | 記事の題名と本文 |
| ガチャかどうか、ラインナップ数、種別 | 価格、サイズ、素材などの商品説明 |
| 発売日と対象試合（`matches.json` の `id`） | 公式の商品画像 |
| 出典URLと確認日 | |

**この線引きは今回新たに決めたものです。**既存の方針から自動的に導かれるものではないため、
判断が違う場合は本節を直してください。

### 取得の自動化

`ticket-sales-sync.yml` と同じ形（`fetch` と `parse` を分け、1日1回、差分があればPRを作る）で
自動化できます。**本PRでは作っていません。**告知は毎試合出るため、手で足し続けるのは続きません。

## `goods.json` のスキーマ

商品は選択式にします。表記ゆれを消すことが目的なので、自由入力にはしません。

```json
{
  "updatedAt": "2026-09-09",
  "hashtags": ["#サンガガチャ交換", "#サンガグッズ交換", "#京都サンガ"],
  "goods": [
    {
      "id": "victory-gacha-1",
      "name": "VICTORY ガチャ【第一弾】",
      "aliases": ["ビクトリーガチャ", "VICTORYガチャ"],
      "kind": "gacha",
      "unit": "number",
      "variants": [],
      "lineup": 35,
      "releasedAt": "2026-09-11",
      "matchId": "sec07",
      "tags": ["#サンガガチャ交換"],
      "source": "https://www.sanga-fc.jp/news/detail/21402",
      "checkedAt": "2026-09-09"
    }
  ]
}
```

| フィールド | 意味 |
| --- | --- |
| `id` | 内部ID。LocalStorageと検索クエリの組み立てに使う。変更しない |
| `name` | 投稿文に出す正式名称 |
| `aliases` | 表記ゆれ。**検索クエリの組み立てに使う**（`ユニ型缶バッジ` と `ユニホーム缶バッチ`） |
| `kind` | `gacha`（中身が選べない）／ `select`（選んで買える）。交換が起きるのは主に `gacha` |
| `unit` | `number`（背番号で指定する）／ `none`（番号がない商品） |
| `variants` | 種別。空配列なら種別欄を出さない |
| `lineup` | ラインナップの種類数。`null` は未確認 |
| `releasedAt` / `matchId` | 発売日と対象試合（`matches.json` の `id`） |
| `tags` | この商品で使う実在タグ |
| `source` / `checkedAt` | 出典と確認日（`AGENTS.md`の方針） |

`aliases` は表記ゆれを**投稿側では消し、検索側では拾う**ために持ちます。自分は正式名称で書き、
他人の揺れた表記も見つけられる状態にします。

`lineup` は在籍選手数と一致しません。9/11柏戦の告知は「全選手対応(35選手)」で、
`players.json` の有効39件（マスコット2件を含む）とずれています。
どの35人かは告知に書かれていないため、**番号の選択肢は在籍全員のままにし、`lineup` は注記として出すだけ**にしています。

## 出力フォーマット

実際の投稿の書き方に合わせます。背番号はドット区切り、商品名は組ごとに1回だけです。

```text
【交換】京都サンガ
譲）ユニ型缶バッジ（1st） 2福田 8米本 34トレヴィザン 50鈴木
求）同種 9ラファエル 17ソウザ
譲）VICTORY ガチャ【第一弾】 10福岡 44佐藤 62志知
求）同種 83パーサ

9/11(金) ホーム柏戦 / 郵送も可
検索からお気軽にお声かけください

#サンガガチャ交換 #京都サンガ
```

- **背番号には選手名を添えます。**背番号だけだと、覚えていない人が確認したり取り違えたりします。
  実際の投稿にも名前つきのもの（`譲: 31 平賀 求: 25 尹 48 中野`）があります。
  名前は `players.json` の `nameShort` を使います。
- **「同種」は「同じもの」という意味です。**組の中で商品名を1回書き、求の行はそれを受けます。
  組が2つ以上あるとき、どの商品を求めているかがこれで決まります。
- 「譲」が空で「求」だけの組は、求の行に商品名を書きます。
- 先頭を `【交換】京都サンガ` にしているのは、タグを使わない人にもキーワード検索で当たるようにするためです。
- 試合は `matches.json` の `match_date` と `opponent`、`home_away` から組み立てます。
- タグは組ごとの `tags` を重複なくまとめ、`#京都サンガ` を足します。
- 締めの一文は既定で入れ、外せるようにします。

### 選手名を外せるようにする

名前は1人あたり重み8前後かかります。上の例（商品2組、背番号10件）で261文字と、280に近づきます。
**「背番号に選手名を添える」を外せるようにし、外すと従来のドット区切りに戻します。**

```text
譲）ユニ型缶バッジ（1st） 2.8.34.50
求）同種 9.17
```

同じ内容が261文字から203文字になります。280を超えているあいだは、
文字数の横に「選手名を外すと収まります」と出して、どこを削れるか分かるようにします。

区切りは、名前を添えるときは `2福田 8米本`（番号と名前のあいだを空けず、組のあいだを空ける）、
添えないときは `2.8.34.50` です。名前が数字で始まることはないため、間に区切りが無くても読めます。
実際の投稿では `31 平賀` のように番号と名前のあいだを空けているものがあり、**ここは合わせていません。**

### 文字数

Xの上限は重み付き280です。日本語は1文字あたり2、半角は1として数えます。
現行ツールは生の `length` を140で比較しており、半角混じりの投稿を不必要に弾きます。
**重み付きで数え直します。**

### 画像

**画像も出します。**Xでは文章より画像が先に見られ、番号の羅列はテキストだと読みにくいためです。
他ジャンルの成功例（[求・譲 画像メーカー](https://apps.apple.com/jp/app/id6756515505)、
[推しトレ](https://mallento.com/recommend/goods-exchange-sites/)）も、出力は画像です。

実装は **`canvas` の2Dだけ**で描きます。1200×675のPNGです。
画像には文字数の制約が無いため、**選手名は常に添えます**（テキスト側は外せます）。

| 判断 | 理由 |
| --- | --- |
| `modern-screenshot` を使わない | 描くのは文字と角丸の四角だけ。DOMを画像化する必要がない。iOS Safariの `foreignObject` 由来の制約もまるごと避けられる |
| `<img>` に出したうえで保存リンクも置く | iOSでは長押し保存が確実。デスクトップは `download` 属性が効く |
| `ctx.roundRect` は無ければ角のまま描く | iOS Safari 16.4より前に無い。角丸は飾りなので落としてよい |

画像には任意でアカウントIDを入れられます。ただし**現物の写真と手書きIDの代わりにはなりません。**
[ID付き画像](https://note.com/oshi_awase/n/n5f617d53b879)は、現物と手書きのIDを一緒に撮ることで
架空取引を防ぐ仕組みで、後から画像に足したIDでは信用されません。画面にもそう書いています。

## LocalStorage

端末内にだけ持ちます。公開JSONへは書きません。

| キー | 内容 |
| --- | --- |
| `sanga.tradePost.draft.v1` | 最後の入力内容（商品、種別、譲・求の番号、試合、締め文の有無） |

既存キーは持っていないため、移行は不要です。取引の進捗管理（`推しグッズ交換メーカー` が持っている機能）は
**今回の範囲外**とし、必要になってから足します。

## 対象外

| やらないこと | 理由 |
| --- | --- |
| チケットの求・譲 | 京都サンガのホームゲームチケットは特定興行入場券（[チケット総合案内](https://www.sanga-fc.jp/ticket)）。定価超の反復継続的な有償譲渡は[チケット不正転売禁止法](https://www.caa.go.jp/policies/policy/consumer_research/white_paper/2020/white_paper_column_11.html)違反にあたる。公式リセールがある。現行ツールのプレースホルダ「定価＋手数料」は定価超であり、例文として出さない |
| 募集の掲載・保管 | 静的サイトのため投稿を預かる先がない。個人情報と通報対応の責任も負えない |
| 取引の仲介・評価 | 同上 |
| 新しいハッシュタグの提唱 | 現行ツールで失敗している |

## 検証

プロトタイプ段階では、`docs/ui-prototype-workflow.md` の確認観点に加えて次を見ます。

- 商品を選ぶと種別欄の出し分けが変わる
- 背番号を複数選んで、既定では `2福田 8米本` の形で並ぶ
- 「背番号に選手名を添える」を外すと `2.8.34.50` に戻り、文字数が減る
- 280を超えたときに「選手名を外すと収まります」が出る
- 商品を複数組のせられ、2組目以降が `求）同種` で受ける
- 組を消すと文面と画像から消える。1組のときは削除ボタンを出さない
- 試合が `matches.json` の今後の試合だけから選べる
- 文字数が重み付き280で数えられている
- 生成した投稿文にタグが実在するものだけ入る
- 画像に商品名・譲・求・受け渡しが入り、背番号の下に選手名が出て、文字が切れていない
- 検索リンクがYahoo!リアルタイム検索とXの両方へ飛ぶ
- スマホ幅で破綻しない、タップ対象が44px程度ある
