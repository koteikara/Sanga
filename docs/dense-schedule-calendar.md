## 目的

京都サンガF.C.は2026/27シーズン、J1・天皇杯・ルヴァンカップ・ACLの4大会を並行して戦います。
`public/data/matches.json`（57件）で試合間隔を数えると、次の状態です。

| 中n日 | 区間数 |
| --- | --- |
| 中2日以下 | 10 |
| 中3日 | 25 |
| 中4日 | 3 |
| 中5〜13日 | 17 |
| 中14日以上（中断期間。2027-01-02〜02-08の38日） | 1 |

年間スケジュールページは試合カードを並べるため、「試合と試合のあいだが何日空くか」は
カード間の日付を読み比べないと分かりません。この画面は、その間隔だけを主役にします。

対象は、日程の詰まり具合そのものを知りたい利用者です。次の試合がいつかを確認する用途は
年間スケジュールページが担当し、こちらは置き換えません。

## 本番の置きどころ

**別ページとして追加します（2026-09-08決定）。** 年間スケジュールページの表示モードには足しません。

### 比較

| 観点 | 別ページ | 年間スケジュールの表示モードへ融合 |
| --- | --- | --- |
| 描くもの | 全日（334行）。試合が無い日が主役 | 既存の表示モードは試合カード57件の見た目違い。行数も対象も別物になる |
| 表示列（1〜4列） | 不要 | 意味を持たないため隠す必要がある |
| 絞り込み | 大会・HOME/AWAYで絞ると間隔が変わるため、そもそも噛み合わない | 絞り込み結果に表示モードを適用する現在の方針（`docs/display-modes.md`）と矛盾する。大半のフィルタを無効化する必要がある |
| 色枠状態（赤・水色） | 対象外 | 22pxの行に3pxの枠線と44pxのタップ領域は入らない。無効化が必要 |
| 共有画像生成 | 対象外 | 約9,900pxの縦長を `modern-screenshot` で1枚にする前提がない |
| 既存への影響 | `app.js`・`style.css`・LocalStorage・`validate-app-contract.js` に触れない | 表示モード・表示列・フィルタ・画像生成のDOM契約すべてに条件分岐が増える |
| 入口 | `public/data/tools.json` に1件足すと入口ページへ出る | 既存利用者は設定パネルを開かないと気づかない |
| 保守 | CSS・JSが1組増える。版数（`?v=`）の対象も増える | 既存ファイルが太る |

融合案は「表示モードを足す」ように見えて、実際には表示列・絞り込み・色枠・画像生成を
まとめて無効化した別画面を同じページの中に作ることになります。得られるのは
「ページを増やさない」ことだけで、`AGENTS.md` の「既存利用者の表示設定、カード状態を壊さない」
「日程表示欄をごちゃつかせない」に対する risk のほうが大きいと判断しました。

役割分担の考え方も別ページ側に立ちます。`docs/service-scope.md` は年間スケジュールページを
「試合予定の確認・パーソナライズ・SNS共有」に集中させ、別の問いは別の画面で扱う方針です。
予想スカッド（`public/squad.html`）とSUPPORTER TIMELINE（`public/timeline.html`）も、
`matches.json` を共有しながら独立したページになっています。

## 画面構成

上から順に、共通トップバー、題（1行）、操作バー、リスト＋ミニマップです。
説明と凡例は操作バーの「使い方」に入れ、画面はできるだけカレンダーへ譲ります
（2026-09-08、実機確認での指摘）。

- **地**: 入口ページと同じネビュラ（`assets/index-nebula.js`）。WebGLが使えなければCSSのぼかしが残る
  進行的強化にする。`prefers-reduced-motion: reduce` と `data-motion="off"` では動きを止める。
  `?nebula=off` でCSSのぼかしと見比べられる（入口ページ・SUPPORTER TIMELINEと同じ）。
- **トップバー**: 公開ページ共通の `assets/topbar.css` を読む。見た目を2か所に持たない。
  画面には固定せず、スクロールで流れて消える。
  仕様は `docs/site-index.md` の「公開ページ共通のトップバー」を正とする。
- **題**: `過密日程カレンダー` と `2026/27` を1行に収める。
- **操作バー**: 「使い方」ボタンを一番左に置き、その右に月ジャンプを枠で囲って並べる。
  囲みの中は「今日」「8月」〜「6月」の順で、先頭の「今日」だけ白地にして目立たせる。
  ミニマップはポインタ専用のため、月ジャンプがキーボードと支援技術の導線を兼ねる。
- **今日**: 日本時間の今日の行に、左の太線・枠・「今日」の印を付ける。間隔の色は消さない。
  ミニマップにも位置を線で入れる。詳しくは「今日の扱い」。
- **「使い方」**: 説明、間隔の色、大会の色、未確定の扱い、出典、免責をまとめた `<dialog>`。
  Esc・フォーカスの閉じ込め・閉じたあとのフォーカス復帰は `showModal()` の標準の挙動に任せ、
  背面のスクロール止めだけ足す（SUPPORTER TIMELINEのシートと同じ考え方）。

- **幅**: `min(100vw, 700px)`。狭い端末は画面幅いっぱい、広い画面では700pxで止めて中央に置く。
  年間スケジュールの430pxは共有画像の枠を兼ねた数字で、画像化しないこのページには当てはまらない。
  700pxにすると対戦相手名が省略されなくなり、月ジャンプの「今日」＋11か月が横スクロール無しで並ぶ。
  縦10,168pxは幅を変えても減らないので、多段組にする案は別途とする（「未確定・保留事項」）。
- **リスト**: 1月〜12月ではなくシーズン（2026年8月〜2027年6月、334日）を縦1本に積む。
- **月見出し**: 月ごとの `section` の先頭に置き、画面上端へ貼り付ける。
  年と、その月の試合数・最短の中n日を出す。月ごとに `section` を分けるのは、
  次の月に入ったら前の月の見出しを外すため。スクロール中に画面へ残る唯一の飾りにする。
- **日付ボックス**: 高さ22px。日付の数字、曜日の丸バッジ、間隔の先頭には「中n日」。
- **試合日ボックス**: 高さ36px。日付、曜日バッジ、`vs 相手`、HOME/AWAYの丸、右端に大会バッジ。
- **ミニマップ**: 右端に貼り付く縦帯。各日の色をそのまま縮小し、表示範囲を枠で示す。
  タップでその位置へ、ドラッグで追従。


### 曜日バッジ

| 条件 | 明るい面 | 濃い面（中2日以下・試合日） |
| --- | --- | --- |
| 土曜 | 青丸に白文字 | 白丸に青文字 |
| 日曜・祝日 | 赤丸に白文字 | 白丸に赤文字 |
| 平日 | 枠線のみの丸 | 白い枠線のみの丸 |

`home_away` が空の試合（勝ち上がり前提のカップ戦など）はバッジを出しません。

## 今日の扱い

2026-09-08に追加しました。

### 日本時間で決める

```js
var TODAY_KEY = new Date().toLocaleDateString("sv-SE", { timeZone: "Asia/Tokyo" });
```

端末のタイムゾーンではなく日本時間で決めます。日程がJSTなので、遠征先の時計で見ても暦とずれません
（実測でロサンゼルスの端末は1日前になります）。`sv-SE` ロケールは `YYYY-MM-DD` を返すので、
画面が使う日付キーとそのまま突き合わせられます。

判定は毎回ブラウザ側で走るため、HTMLがキャッシュされていても今日は正しく出ます。

### 見せ方

| 場所 | 出し方 |
| --- | --- |
| 日付・試合日ボックス | 左の太線（`inset 4px`）と枠。どちらも `currentColor` なので、明るい帯でも中2日以下の濃い帯でも読める色になる |
| 同上 | 「今日」の印。色だけに頼らないため文字でも出す |
| ミニマップ | 白で縁取った黒い線。どの帯の色の上でも見える |
| 操作バー | 先頭に「今日」。**押したときだけ**その日へ移動する（開いたときの自動移動はしない） |

シーズンの外（6月末〜7月）に開いたときは、印も「今日」も出ません。壊れはしません。

「今日」は `<a href="#today">` です。JavaScriptが動かない環境でも素のアンカーとして着地します。

### 移動のしかた

月ジャンプ・「今日」・ミニマップのタップは、いずれも自前のアニメーションで動かします。
ブラウザ標準の `behavior: "smooth"` は速度カーブを変えられず、最後に余韻を残して止められないためです。

| 項目 | 値 |
| --- | --- |
| カーブ | easeInOutCubic（前半 `4t^3`、後半 `1 - (-2t+2)^3 / 2`） |
| 時間 | `320ms + 距離 × 0.45`、下限420ms・上限2000ms |
| 着地点 | 貼り付く月見出しに隠れないよう36px下げる |
| 中断 | `wheel` / `touchstart` / `keydown` が来たら止めて、利用者の操作を優先する |
| 動きを減らす設定 | `prefers-reduced-motion: reduce` と `data-motion="off"` では即座に移動する |

最初は片側だけの easeOutCubic（`1 - (1-t)^3`）で、上限1300msにしていました。これは
最初のフレームが最速なので、月ジャンプのような長い移動だと出だしが一瞬で流れてしまい、
実機では減速していることが読み取れませんでした（2026-09-08、実機確認での指摘）。
両側にして出だしを立ち上げると加速と減速の対比が出て、止まり際が余韻として見えます。
5乗（easeOutQuint）も試しましたが、半分の時間で97%進んでしまい、残りが「わずかに這う」だけでした。

実測（幅390px、8,837pxの移動）: 500ms→6%、750ms→21%、1,000ms→50%、1,250ms→78%、
1,500ms→94%、1,750ms→99%、約2,000msで停止。最後の6%（約530px）に500msかけます。

移動先がページの末尾を越えるときは `scrollHeight - innerHeight` で止めます。最終月へのジャンプが
目標より17px手前で止まるのはこのためで、ずれではありません。

ミニマップのドラッグだけは指に追従させるため、アニメーションを挟まず即座に動かします。

## 危険度の決め方

試合が無い日が連続する区間を1つの「間隔」として扱い、その長さをそのまま中n日にします。
指示にある `中n日 = 次の試合日 − 前の試合日 − 1` と同じ値になり、
画面に描いた試合日と必ず一致します。

| 中n日 | 危険度 | 色 |
| --- | --- | --- |
| 中2日以下 | 危険 | `#c8402e` |
| 中3日 | 注意 | `#e08a2e` |
| 中4日 | やや注意 | `#e3b23c` |
| 中5〜13日 | 安全 | `#7fa687` |
| 中14日以上 | 中断期間（中立） | `#edeae3` |
| 前後どちらかに試合が無い期間 | 中立 | `#edeae3` |

指示にあった5段階に、6段目として「中14日以上」を足しています（2026-09-08決定）。
2027年1月2日〜2月8日の38日間を中6日と同じ緑にすると「安全」の意味が薄れるためです。
中断期間とシーズン前後は同じ中立色にし、中断期間には中n日の文字が付くことで区別します。

区間内のすべての日を同じ色にします。グラデーションにはしません。

色だけに頼らないよう、区間の先頭の日に「中n日」を文字でも出します。
試合日が連続して間の日が無い場合（中0日）は文字を置く行が無いため、
後ろの試合日ボックスに「中0日」の印を付けます。

## 未確定日程の扱い

`matches.json` 57件のうち26件が `status: tentative` で、うち17件は `match_date` を持たず
`date_candidates`（多くは土日の2日組）だけを持ちます。

- 候補日すべてに点線の試合日ボックスを置き、`候補1/2` `候補2/2` を添える。
- 候補日も「試合が入りうる日」として間隔の計算に入れる。結果としていちばん詰まった読み方になる。
- 未確定の試合に接する区間には斜線を掛け、確定した間隔と区別する。
  斜線は薄い墨（`rgba(28,25,34,.12)`、2px幅・6px間隔）にする。白い斜線だと中立の帯（`#edeae3`）の
  上で見えなくなるうえ、中2日以下（`#c8402e`）の上で白文字のコントラストを下げるため。

例: 2027年2月13日・14日（第21節の候補）と2月16日（ACL）のあいだは、13日開催なら中2日、
14日開催なら中1日です。中1日として描き、斜線で確定でないことを示します。

`AGENTS.md` の「不確定情報は `tentative`、候補日、注記で明示する」に対応する扱いです。

祝日法第3条第2項・第3項による「休日」（2026-05-06、2026-09-22、2027-03-22）も含みます。

- 機械可読版: https://www8.cao.go.jp/chosei/shukujitsu/syukujitsu.csv

  中14日以上（中断期間）で38日、シーズン前後の中立で32日になること。
- 月見出しが画面上端に貼り付き、次の月で入れ替わること。
- ミニマップの表示範囲枠がスクロールに追従し、タップとドラッグで移動できること。
- 幅320pxで対戦相手名が省略記号になるのは12文字の2件（`ニューカッスル・ジェッツ`、
  `ブリーラム・ユナイテッド`）だけであること。
- `npm run check` が全項目成功すること（`public/` を変更していないため既存検証に影響しない）。

実機（iPhone Safari・Android Chrome）では、月見出しの貼り付き、ミニマップのタップとドラッグ、
10〜11月の色の読み取り、2027年2月以降の斜線について問題がないことを確認済みです（2026-09-08）。

公開版（`public/calendar.html`）でも、Chromium（幅320px・390px）で11か月・71ボックス・
候補日のHOMEバッジ15個が描かれ、ネビュラが動き、横スクロールが出ないことを確認しています。

幅の上限を700pxへ広げたあとに、Chromiumで幅320/390/430/768/1280/1920pxを測り直しました
（2026-09-08）。

| --- | --- | --- | --- | --- |

幅430px以下は数値が以前と同じで、スマートフォンの見え方は変わっていません。
「使い方」も同じ700pxまで広げ、本文だけ `max-width` で止めています（幅1280pxで本文408px）。

その確認のあとに直したものが2つあります。

- **候補日のHOMEバッジが見えなかった。** `.is-candidate .ha-h` が同じルールで
  `background:currentColor` と `color:var(--paper)` を指定していたため、`currentColor` が
  `--paper` に解決され、白地に白文字になっていました。候補日だけを持つHOMEの8試合
  （sec21/23/24/26/28/32/35/37）が該当します。大会色を `--comp` に逃がして直しました。
  `matches.json` 側にHOME/AWAYが無いのは、勝ち上がり前提で対戦相手も会場も未定の
  カップ戦8件（天皇杯6・ルヴァン2）だけで、こちらはデータどおりです。
- 地とトップバー、文言を上記のとおり作り直しました。

## 決めたこと

| 日付 | 論点 | 決定 |
| --- | --- | --- |
| 2026-09-08 | 中断期間の色 | 6段目として `中14日以上` を中立にする。中6日と同じ緑では「安全」の意味が薄れるため |
| 2026-09-08 | 斜線の量 | 薄い墨（`rgba(28,25,34,.12)`）で2px幅・6px間隔にする。区間を絞る案と切り替えを置く案は採らない |
| 2026-09-08 | 本番の置きどころ | 別ページとして追加する。年間スケジュールの表示モードには足さない |
| 2026-09-08 | 地 | 入口ページと同じネビュラにする。プロトタイプ独自のグラデーションはやめる |
| 2026-09-08 | トップバー | 公開ページ共通の `assets/topbar.css` を読む。プロトタイプに複製しない |
| 2026-09-08 | 文言 | 説明を1文に縮め、凡例を3群に分ける |
| 2026-09-08 | 画面の配分 | 説明と凡例を「使い方」パネルへ移し、月ジャンプは枠で囲って並べ、「使い方」ボタンはその囲みの外の一番左に置く。空いた分をカレンダーに回す（画面上部の飾りが313px→155px、スクロール後は月見出しだけ） |
| 2026-09-08 | トップバー | 画面に固定しない。スクロールで流れて消える |
| 2026-09-08 | 今日の基準 | 端末のタイムゾーンではなく日本時間で決める。日程がJSTのため |
| 2026-09-08 | 今日への移動 | 開いたときの自動移動はしない。操作バーの「今日」を押したときだけ飛ぶ |
| 2026-09-08 | 移動の動き | ブラウザ標準の `behavior: "smooth"` をやめ、自前アニメーションにする。最後に余韻を残して減速させるため |
| 2026-09-08 | 速度カーブ | easeOutCubic では実機で減速が感じられなかったため、easeInOutCubic にして上限を1300ms→2000msへ伸ばす |
| 2026-09-08 | 広い画面 | 幅の上限を430px→700pxへ広げるだけにする。多段組は今回は入れない |

## 見た目を変えたときにやること

公開後にこのページの見た目を変えたら、入口ページのサムネイルを撮り直します
（`docs/ui-prototype-workflow.md` の「入口ページのサムネイル撮り直し」）。
出力先は `public/assets/thumbs/dense-calendar.webp` と
`experiments/site-index/thumbs/dense-calendar.webp` の2か所です。
撮ったあとに `npm run fix:asset-versions` を実行してください。名前が同じままなので、
版数を上げないと再訪した人には古い画像が使われ続けます。

## 未確定・保留事項

1. **幅320pxでの対戦相手名**。大会名バッジを右端に固定するため、12文字の2件
   （`ニューカッスル・ジェッツ`、`ブリーラム・ユナイテッド`）は省略記号になります。
   幅390px以上では省略されません。
2. **広い画面の多段組**。幅を700pxにしても縦10,168px（334日×22px＋71箱×36px＋月見出し11本）は
   変わらず、表示領域900pxのPCでは11画面分のスクロールが残ります。月ブロックを横に並べれば
   3列で約3,400px、4列で約2,500pxになり、シーズンの1/3〜1/2が一度に入ります。
   間隔の色は区間をまたぐ枠ではなく1日ごとの `<li>` に付いているので、横に並べても色は割れません。
   引っかかるのはミニマップで、縦1本の代理として描いているため多段組とは噛み合いません
   （広い画面では隠すのが素直。隠すと `minimap.clientHeight` が0になり
   `minimapView.style.top` がNaNになるので、`setupMinimap` にガードが要ります）。
3. **DOM契約の検証**。年間スケジュールの `tools/validate-app-contract.js` にあたる検証は
   まだありません。このページが個人状態を持つようになったら用意します。
