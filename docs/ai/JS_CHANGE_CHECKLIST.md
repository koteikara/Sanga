# JS_CHANGE_CHECKLIST.md

## 目的

`public/assets/app.js` を変更するPRで、既存の表示・保存・操作仕様を壊さないための確認項目です。

**自動検証で確認できる項目はここに載せません。** 二重管理すると必ずずれ、
「読んだのに守れていない」状態になるためです。このファイルに残すのは、
スクリプトでは判定できない、人間の目と判断が必要な項目だけです。

## 1. 自動検証（手で確認しない）

```bash
npm run check:static
```

これが通れば、次はすべて確認済みです。同じ内容を目視で再確認する必要はありません。

- LocalStorageキー4種の文字列（`sanga-schedule-button-states-v1` ほか）
- LocalStorage読み書きヘルパーと状態永続化関数の存在
- `data/matches.json` の読み込みパス、公開JSONの件数と形式
- HTMLからのCSS/JS参照、CSS波括弧数
- 表示列 `1 / 2 / 3 / 4` の値・ラベル・CSSクラス、`layout-2` を新設していないこと
- 表示モード `card / compact` の値・ラベル・CSSクラス
- フィルタ12種の値・ラベル・定義、大会フィルタと `competition` 値の対応
- カード状態 `0 / 1 / 2` の正規化とフィルタ連動
- 共有画像の生成処理、状態クラス、プレビューのalt属性
- パネル閉じる待機時間 `PANEL_CLOSE_DELAY_MS=240`
- DOM識別子一覧（`docs/dom-inventory.md`）が実装と一致していること

失敗した場合は、まず実装を直します。検証スクリプト側を緩めて通す対応はしません。

## 2. 人間しか確認できないこと

### 変更の妥当性

- [ ] この変更が `public/assets/app.js` に必要であることを説明できる。
- [ ] 変更対象外の機能（特に共有画像関連）へ巻き込みで触れていない。
- [ ] class名・id名・data属性を変更する場合、`docs/dom-inventory.md` で参照箇所を確認した。
- [ ] LocalStorageの保存形式を変えた場合、旧形式の読み取り互換または移行処理がある。
- [ ] 新しいLocalStorageキーを追加した場合、追加理由と移行方針を記録している。

### 毎回のスモークチェック

実ブラウザ確認の詳細は `docs/ai/BROWSER_CHECKLIST.md` の「通常確認: 7項目」に従います。

- [ ] スマホ幅とPC幅で主要表示が大きく崩れていない。
- [ ] 表示列変更が動く。
- [ ] 使い方ダイアログが開閉できる。
- [ ] LocalStorage削除ボタンが動く。
- [ ] ブラウザコンソールに赤いJavaScriptエラーが出ていない。

問題がなければ「7項目スモークチェック問題なし」と短く記録します。
問題が出た場合だけ、再現手順と画面幅を残します。

## 3. 変更内容別の追加確認

触った機能に対応する節だけを確認します。いずれも実際に操作しないと分からない項目です。

### LocalStorage

- [ ] 保存内容削除で、タップ状態・フィルタ・表示列・表示モードが初期状態へ戻る。
- [ ] 削除ボタンの削除対象と、画面上の説明文が一致している。
- [ ] LocalStorageを使えない環境でも、保存されないだけで画面の切り替えは動く。
- [ ] LocalStorage利用不可時の利用者向け文言を不用意に変更していない。

### 表示列・表示モード

- [ ] 1列・2列・3列・4列の切替が動き、再読み込み後に復元される。
- [ ] カード表示とコンパクト表示の切替が動き、再読み込み後に復元される。
- [ ] 保存内容削除後に `2列 / 通常カード` へ戻る。
- [ ] 選択状態と `aria-pressed` が一致している。
- [ ] 共有画像生成に現在の表示列・表示モードが反映される。

### フィルタ

- [ ] 件数表示が現在の絞り込み結果と一致している。
- [ ] 該当なしの場合の空メッセージが崩れていない。
- [ ] 年見出しの表示・非表示が絞り込み結果と一致し、0件時に年見出しだけが残らない。
- [ ] 選択状態と `aria-pressed` が一致している。
- [ ] 共有画像生成に現在のフィルタ結果が反映される。
- [ ] フィルタ定義を変えた場合、`docs/filtering.md` を同じPRで更新した。

### 使い方ダイアログ・設定パネル

- [ ] 開閉できる。Escapeで閉じる。背景オーバーレイ操作の挙動が意図どおり。
- [ ] `aria-expanded`、`aria-hidden`、`hidden` の更新が表示状態と一致している。
- [ ] フォーカス移動が破綻していない。背面がスクロールしない。

### JSON読み込み・カード描画

- [ ] 候補日、未定、注記、HOME/AWAY、会場が表示される。
- [ ] 対戦相手名、節、日付、曜日、年見出しが崩れていない。
- [ ] データ欠損時にも画面全体が破綻しない。

### 共有画像

- [ ] 今回触る必要があることを、変更前にPRまたはWORKLOGへ記録している。
- [ ] CDN依存があるため、静的検証だけで完了扱いにしていない。
- [ ] 生成ボタンが動き、保存リンクと保存導線が表示される。
- [ ] 生成中・成功・失敗の状態表示が分かる。
- [ ] 終了ボタンで共有画像モードを終了できる。

## 4. 変更してはいけないもの

明示的な依頼や移行方針がない限り、次は変更しません。1の自動検証が検知します。

- LocalStorageの既存キー名と保存形式の互換性
- `matches.json` の読み込みパス
- `match.id` とカード状態保存の紐づき
- HTML・CSS側の既存id/class/data属性との連動
- 使い方ダイアログ、設定パネル、削除ボタンのキーボード操作性
- 共有画像生成まわりの処理（明示的に対象の場合を除く）

## 5. 問題が出た場合の記録

WORKLOGまたはPR本文へ簡潔に記録します。

- 確認日 / 対象PR / 変更した機能
- 問題が出た項目、再現手順、期待結果、実際の結果
- 修正方針または後続課題
