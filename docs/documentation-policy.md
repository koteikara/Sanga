# ドキュメント管理方針

## 目的

実装者が作業前に必要文書を確認し、実装と現行仕様の不一致を残さないための基準です。

## 必要な文書の種類

| 種類 | 目的 | 例 | 更新条件 |
| --- | --- | --- | --- |
| プロジェクト概要 | 公開サービスと現在構成を把握する | `README.md`、`docs/project-structure.md` | 公開ページ、主要データ、構成が変わったとき |
| 実装ルール | 制約と作業手順を定める | `AGENTS.md`、`docs/codex-workflow.md` | 開発・PRルールが変わったとき |
| 現行仕様 | 現在の画面、データ、保存形式を説明する | `docs/data-schema.md`、`docs/squad-builder.md` | 実装や利用者向け挙動が変わったとき |
| 運用手順 | 更新・検証・本番反映を再現可能にする | `docs/operation-flow.md`、`docs/deploy-policy.md` | コマンド、件数、Actions、手順が変わったとき |
| チェックリスト | 完了条件と人間の確認項目を示す | `docs/ai/CHECKLIST.md`、ブラウザチェックリスト | UI、検証対象、対応環境が変わったとき |
| 目標・計画 | 今回の範囲と完了条件を固定する | `docs/ai/GOAL.md`、`docs/ai/PLAN.md` | 作業開始・計画変更時 |
| 作業記録 | 実施内容、確認結果、残課題を残す | `docs/ai/WORKLOG.md` | 将来の保守に必要な作業完了時 |
| 調査・判断記録 | 採用理由、比較、制約を残す | `docs/*-research.md`、実装計画書 | 技術・設計判断時 |
| 出典・権利管理 | 素材・データ・ライブラリの由来と利用条件を残す | `docs/source-and-license.md`、`THIRD_PARTY_NOTICES.md` | 外部由来の素材・データ・依存物を追加・更新・削除するとき |
| アーカイブ | 完了済み計画と古い記録を保管する | `docs/archive/` | 現行文書として不要になったとき |

## 実装者が必ず読む順序

1. `AGENTS.md`
2. 本文書
3. `docs/project-structure.md`
4. `AGENTS.md` が変更対象別に指定する仕様書・手順書・チェックリスト

## 現行文書に必要な内容

- 目的と対象範囲
- 現在の実装状態
- 正本となるファイルまたはデータ
- 互換性・変更禁止事項
- 実装または運用手順
- 検証方法と完了条件
- 未実装・未確認・保留事項
- 関連文書
- 状態や数値を確認した日付

古い計画と現在仕様が同居する場合、冒頭で現在状態を示し、過去の指示を現在の作業指示と誤認させないようにします。

## 同じPRで更新する条件

- 表示、文言、操作、保存内容を変える。
- JSON、CSV、LocalStorage、URL、ファイル構成を変える。
- 検証コマンド、期待件数、Actions、デプロイ手順を変える。
- 対応ブラウザや既知の制約が変わる。
- 機能の状態が未実装・検証中・公開済み等に変わる。
- 外部由来の画像、文章、データ、フォント、ライブラリを追加・更新・削除する。
- 次回の実装者が知る必要がある判断を行う。

文書更新が不要な場合も、PR本文で理由を記載します。

## 数値と履歴

- 現在値はコード、JSON、Actions設定を確認して記載する。
- 過去のWORKLOG、検証記録、日付付きスナップショットは書き換えない。
- スナップショットには基準日を付け、現在値と区別する。
- 「今後」「検討中」にはロードマップ項目または判断条件を添える。
- 現在仕様を文書末尾への追記だけで更新しない。

## 追加・統合・アーカイブ・削除

- 追加: 既存文書へ統合すると目的と必読範囲が不明確になる場合だけ追加する。
- 統合: 重複仕様は正本を1つに決め、他文書から参照する。
- アーカイブ: 完了済み計画や古い調査を `docs/archive/` へ移し、現行ルールと誤認されないよう状態と移動元を明示する。
- 削除: 履歴価値、参照、復元の必要がないと確認し、PRに理由を記載できる場合だけ行う。

## PR完了前チェック

- [ ] 必読文書を確認した。
- [ ] 実装と現行文書の状態・件数・ファイル名が一致している。
- [ ] 仕様変更に対応する仕様書とチェックリストを更新した。
- [ ] 検証・デプロイ変更に対応する運用手順を更新した。
- [ ] 過去の記録を現在仕様として書き換えていない。
- [ ] 未確認事項と別PRの範囲を明記した。
- [ ] 外部由来の素材・データ・依存物を変更した場合、出典、確認日、利用条件、許諾状況を更新した。
