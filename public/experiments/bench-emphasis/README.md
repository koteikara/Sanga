# ベンチ強調オプション（比較プロトタイプ）

作成日: 2026-08-21

## 目的

予想スカッドのベンチをもっと目立たせたい、という要望に対し、現行の見せ方を残したまま
オプションで切り替えられるかを、移植前に見た目で確認する。

確認するのは次の2軸の組み合わせ（4通り）。

| | 標準 | 大きめ |
| --- | --- | --- |
| チップ（現行） | A | B |
| 背番号タイル | C | D |

名前の表記は本番の「日本語名を併記」に従属させる想定のため、この軸は増やしていない。

## 確認方法

GitHub Pagesで次を開く。

```text
https://koteikara.github.io/Sanga/experiments/bench-emphasis/prototype.html
```

キャンバスは本番ページ `squad.html` を同一オリジンのiframeで読み込み、ベンチだけを
差し替えている。配置計算・画像・スタイル切替は本番のコードがそのまま動くので、
移植したときの見え方と一致する。

操作できるのは、キャンバス幅（320 / 375 / 420px）、控えの人数（6 / 9 / 12人）、
控えの顔ぶれ、スタイル（8種類）、タイルの名前（省略名を出す / 背番号だけ）、大きめの効かせ方。

控えの顔ぶれは2つ用意している。

| 選択肢 | 内容 | 目的 |
| --- | --- | --- |
| 見分けにくい組み合わせ | マセイオ／ウェベルトン、福田／福岡、平岡／平賀／平戸、加藤／加藤蓮 | 名前の判別 |
| ローマ字名が長い順 | JOÃO PEDRO、H.TREVISAN、ALEX SOUZA ほか | チップ表示の折り返し |

短い名前ばかりだと折り返しがたまたまきれいに収まるため、必ず両方を見る。

### GitHub Pagesで見えない場合

Pagesは `main` への push でのみデプロイされる（`.github/workflows/pages.yml`）。
PRブランチの内容は公開されないため、マージ前にURLを開くと404になる。
確認する方法は次のどちらか。

* このPRを `main` へマージする（プロトタイプは `public/experiments/` 配下で、本番ページからは
  リンクしていないため、公開されても通常の導線には出ない）
* Actionsの「GitHub Pages確認環境」を `workflow_dispatch` で対象ブランチを指定して実行する
  （次に `main` へpushされるまで、Pagesはそのブランチの内容になる点に注意）

## 構成

| ファイル | 内容 |
| --- | --- |
| `prototype.html` | 操作パネルと4枚の比較枠 |
| `prototype.js` | iframeの操作、ベンチの組み替え、名前の圧縮 |
| `prototype.css` | 比較画面そのものの見た目 |
| `bench-overlay.css.js` | iframeへ差し込むベンチのCSS。**本番へ移植するのはこの中身** |
| `name-short.js` | ベンチ表示用の省略名39人分。確定後は `players.json` の `nameShort` へ移す |

## 設計の要点

* 見せ方はキャンバスの `data-bench-format`（chip / tile）で分岐する。
  `:has()` は iPhone Safari 15系にないため使わない。
* 大きさは `--bench-emphasis`（1 / 1.35）の**倍率**で持ち、人数に応じた既存の
  自動縮小 `--bench-scale` と掛け算する。見せ方が増えても、はみ出しを防ぐ仕組みは1本のまま。
* フッターの上限だけ見せ方ごとに変える（chip 24% / tile 32%）。
  ピッチの `min-height:60%` は変えない。
* 長い省略名は、カード名と同じ「収まらないときだけ横方向へ圧縮」を使う。

## 実測（2026-08-21・Chromium）

420px・控え9人・モダンでの比較。

| | ベンチ1件の幅 | 標準比 | フッター比 | ピッチ比 | カード高さ |
| --- | --- | --- | --- | --- | --- |
| A チップ×標準 | 65.2px | — | 11.4% | 69.9% | 75.1px |
| B チップ×大きめ | 86.6px | 1.33倍 | 17.1% | 64.2% | 72.0px |
| C タイル×標準 | 28.3px | — | 11.5% | 69.9% | 75.1px |
| D タイル×大きめ | 41.3px | 1.46倍 | 21.3% | 60.0% | 66.0px |

控え12人では、420pxで D 37.6px（カード66.3px）、320pxで D 28.2px（カード48.3px）。
4通りとも、どの幅・人数でも見切れは発生しない。

## わかったこと

1. **倍率は見せ方ごとに変える必要がある。**
   本番の `layoutPitch()` は、カードが下限（70px）に張り付くとベンチ側を自動で縮めて
   ピッチの取り分を増やす。縮小できる幅は最大0.2ぶんなので、タイルで1.35倍にしても
   ほぼ打ち消されていた（28.3→29.4pxで4%増）。倍率をチップ1.35 / タイル1.9に分けると、
   タイルでも1.46倍まで効く。ベンチが大きくなったぶん、カードは75.1→66.0pxへ縮む。
   「ベンチを大きくする＝スタメンを小さくする」という取引がそのまま見た目に出る。
2. **縮小率を戻すだけでは解決しない。**
   ベンチ優先として `--bench-scale` を基準値へ戻すと円は大きくなるが、カード高さを
   再計算していないためピッチ下端のカード（GK）がはみ出す。倍率で調整するほうが、
   本番の再計算に乗るぶん安全（プロトタイプの「ベンチ優先」は暫定確認用として残している）。
3. **タイルは角丸の四角にする。**
   円にするとシンプルのスタメン（円）と紛らわしく、盾型カードとの差も出にくい。
   角丸の四角なら、スタメンが盾でもシンプルの円でも見分けがつき、
   もともと正方形のタイル画像を切り落とさずに大きく見せられる。
4. **チップ表示の折り返しは、控えの顔ぶれで印象が変わる。**
   短い名前が並ぶと折り返しがきれいに揃うが、ローマ字名が長い順にすると
   420px・12人でA・Bとも3行になり、最終行が2件だけの不揃いな並びになる。
   はみ出し・見切れは発生しない（実測でどの組み合わせも0件）。
   採用するなら、この不揃いを許容するかどうかの判断がいる。
5. **省略名は4文字前後で頭打ち。**
   名前欄の幅は円の直径に比例するため、幅や人数によらず約4.2文字ぶん。
   「ウェベルトン」「トレヴィザン」は横圧縮がかかるが判読できる。

## 未確認・次の判断

* 背番号タイル画像は `docs/source-and-license.md` で利用許諾が未確認と整理されている素材。
  ベンチにも使うと使用箇所が増えるため、暫定判断の範囲内として扱ってよいか要確認。
* 「大きめ」をタイルで実際に効かせるか（＝カード高さの下限を緩めるか）の判断。
* iPhone Safariでの表示とPNG生成は未確認。
* 本番移植時の検証は、既存の全組み合わせに掛けず、
  「4パターン × 8スタイル × 3幅 × 控え12人 × 代表フォーメーション2 = 192通り」を追加する想定。
