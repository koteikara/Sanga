## 概要

- チケット販売スケジュールの自動取り込みです（`.github/workflows/ticket-sales-sync.yml`）。手作業の編集は含みません。
- 内容を確認してからマージしてください。自動ではマージしません。
- 変わったデータ: 公式の販売スケジュール、アウェイ席の販売状態（Jリーグチケット）
- **公開JSONを変更するPRです。** 取り込んだCSVから `public/data/calendar-events.json` を作り直しています。公開ページ（`public/timeline.html`）が読むデータです。
- **購読フィード（`public/timeline.ics`）も変わります。** マージすると購読している人のカレンダーに届きます。予定が消えていないかは特に確認してください。
- アウェイ席は、発売中の試合に加え**発売前の試合も載ります**。**ただし載っていない試合は「発売前」ではありません**（別のプレイガイドで売っている場合があります）。
- **公式の案内の取り込みは失敗しました。** 案内のCSVは前回の値のままです。
- 取得日時・確認日・画面表示（受付中・販売中）だけの違いでは更新しません。

## 変更内容

取得日時の列は毎回動くため、CSVの差分はそのぶん多く見えます。その列を除いて突き合わせた結果です。

### 公式の販売スケジュール（`docs/sheets/ticket-sales.current.csv`）

```text
書きました: docs/sheets/ticket-sales.current.csv
変更: 第1節 一般販売 / sale_start: 2030-07-05T12:00:00+09:00 → 2030-07-06T12:00:00+09:00
```

### アウェイ席の販売状態（Jリーグチケット）（`docs/sheets/away-tickets.current.csv`）

```text
変更: 2030-07-14 / state_raw: 発売前 → 空席あり
```

### 公開ファイル

- `public/data/calendar-events.json`
- `public/timeline.ics`

## 確認内容

- 取り込み時に `npm run check:static`（`check:timeline` → `check:timeline:public` を含む）を実行し、合格しています。
- GitHub Actionsが作ったPRではワークフローが起動しないため、このPRにはCIの結果が付きません。

## 注意点

- 販売日時の変更が、公式ページの表示と一致しているか。
- 掲載済みだった試合が未掲載に戻っていないか（戻っている場合は取得の失敗を疑う）。
- アウェイ席の販売状態・発売日時が、Jリーグチケットの試合ページの表示と一致しているか。
- 購読フィードから予定が消えていないか。
- 本番反映はマージと別に、手動のデプロイで行います。
